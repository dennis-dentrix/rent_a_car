# Car Rental Platform

Premium car hire and executive transport platform for Kenya. Mobile first. Owned fleet first, with private-owner vehicles recorded from the start.

Read `docs/CLAUDE.md` before any work: it holds the document map, precedence order, working rulings, and the build plan.

@docs/CLAUDE.md

## Project rules (from the owner)

- Never commit or push. The owner reviews and commits.
- No co-author, "generated by", or AI attribution in commits, files, or comments.
- Keep the file structure below. No stray files, no scratch files, no sample data.
- Any document I create (plans, notes, specs, reports) is saved in `docs/`, never elsewhere in the project.
- Every secret lives in `.env.local` files, which are git-ignored. Commit only `.env.example` files with placeholder values.
- Brand names and colours live in one file, `packages/shared/src/brand.js`. Component code never contains a brand name or colour. The web app's tokens and Tailwind config read from it.
- Extract repeated logic into a shared module before its third use. In practice the owner wants no copies at all: `npm run check` runs lint (functions over 40 lines fail), formatting, a duplicate-code scan (`jscpd`, zero tolerance, JavaScript and SQL), and the unit tests. Run it before finishing any change.

## Stack

JavaScript (no TypeScript). Two separate applications in an npm-workspaces monorepo (owner decision, architecture doc): the frontend is Next.js, React, and Tailwind CSS; the backend is Express. Zod validates every boundary, with the schemas in a shared package. Supabase (Postgres, Auth, RLS), Tingg, ZeptoMail, Mobile Sasa, Sentry, PostHog, Google Maps Embed. Cloudflare for DNS, WAF, rate limits, cron, queues, and R2. Each app is a Docker container on Oracle Cloud behind Caddy. Vitest with supertest, Playwright, Lighthouse CI, GitHub Actions.

## Layout

```
apps/web/        Next.js frontend: app/ (routes), components/, copy/, styles/tokens/, public/
apps/api/        Express backend
  src/routes/      routers, one per area (catalogue, bookings, staff, admin, internal)
  src/middleware/  auth and roles, response envelope, error handler, job secret
  src/services/    business logic: pricing, quotes, bookings, vehicles, owners, trackers, inspections
  src/domain/      status transition table and pure rules, no framework imports
  src/lib/         Supabase clients, errors, logger, pagination
  tests/           database and API tests (tests/integration)
packages/shared/ Zod schemas, money and date rules, error codes, constants, brand
supabase/        migrations, RLS policies, seed data (shared infrastructure)
deploy/          Caddyfile, compose.yaml, .env.example for the Oracle VM
docs/            specifications, API testing guide, Postman collection
```

Plus standard project files at the root only: `package.json`, `.npmrc`, `README.md`, lockfile, lint, format, and duplicate-scan config, `.dockerignore`, `.gitignore`. Each app has its own `.env.example` and `Dockerfile`.

Rules for the split: the web app never queries the database; it calls the API. The API owns business rules, pricing, status changes, payments, document access, role checks, and the Supabase service key. The shared package holds only what both must agree on, and never imports from an app.

## Coding rules (pack section 14, condensed)

- One source per fact: prices in `apps/api/src/services/pricing.js`, statuses in `apps/api/src/domain/booking-status.js`, validation schemas, money, dates, and error codes in `packages/shared`, text in `apps/web/copy/`.
- Money is integer KES. No floats. Round once, at the final total.
- Store UTC; display Africa/Nairobi only in display code.
- The server computes price, status, and role. Never trust the browser.
- Functions about 40 lines, three levels of nesting at most, files under 300 lines, no nested ternaries, no commented-out code, no `console.log` (use the logger).
- Business constants (deposit percent, grace period, minimum hire days) live in the `settings` table, not code.
- Every external call has a timeout and a failure path. Webhooks return success only after the change is saved.
- A bug fix starts with a failing test. Tests take dates as arguments.
- Add a dependency only when writing it ourselves is long and risky. Record each one in the decision log.

## Commands

- `npm run dev:api` and `npm run dev:web` run the apps (API on 4000, web on 3000).
- `npm run db:start` and `npm run db:reset` run the local Supabase.
- `npm test` unit tests; `npm run test:db` database and API tests (needs the local Supabase and `apps/api/.env.local`).
- `docker compose up -d --build` in `deploy/` runs the whole stack (see `docs/deployment.md`).
- `npm run check` lint, format, duplicate scan, and unit tests.
