# Decision Log: Packages Added

Each package is added only when writing it ourselves would be long and risky (pack section 14). One entry per package, with the reason.

| Date | Package | Where | Why |
| --- | --- | --- | --- |
| 15 Nov 2026 | `pdf-lib` 1.17.1 | `apps/api` | Builds the rental agreement PDF. Pure JavaScript with no native parts, so the Docker image stays simple. Writing a PDF writer ourselves would be long and easy to get wrong. It uses the standard PDF fonts, so letters outside Western European languages print as the nearest plain letter or `?`; embedding a Unicode font (which needs a second package, `@pdf-lib/fontkit`, and a font file) is the fix if the owner needs full international names in the PDF. |
| 22 Nov 2026 | `wrangler` 4.166.0 | `apps/api` (dev dependency) | Builds, runs locally, and deploys the API to Cloudflare Workers. It is Cloudflare's own tool and the only supported way to deploy a Worker, so there is nothing to write ourselves. It is a build tool and is not part of the running API. |
| 24 Nov 2026 | `@supabase/supabase-js` 2.119.0 | `apps/web` | Signs staff and admin in from the web server: password sign-in, the authenticator-app second factor, and renewing a session. Supabase Auth's token and factor handling is long and easy to get wrong, and the API already uses this exact version. It runs on the server only; the tokens live in cookies the browser's scripts cannot read. |
| 24 Nov 2026 | `@opennextjs/cloudflare` 1.20.18 | `apps/web` | Builds the Next.js app into a Cloudflare Worker, so the web app can run on the same platform as the API. Next.js does not run on Workers by itself, and the adapter is the route Cloudflare documents for it, so there is nothing for us to write. It is a build tool and handles `next/image` through Cloudflare Images. Node middleware (our `proxy.js`) is marked experimental by the adapter; it was checked in a local Workers preview (currency cookie, sign-in redirect). `npm audit` reports 3 moderate advisories in its build-time dependencies (`glob`, `minimatch`); they do not ship in the Worker, and the only fix offered is a downgrade to 0.3.0. |
| 24 Nov 2026 | `wrangler` 4.166.0 | `apps/web` (dev dependency) | Previews and deploys the web Worker. The same version and reason as for the API; the adapter needs `^4.148.0`. |
| 24 Nov 2026 | `cookie` 0.7.2 (override) | root `package.json`, for `@opennextjs/aws` | The adapter asks for `cookie` ^1.1.1 and imports it as a default export. Once bundled into the Worker, that import is empty, so every request that carried a cookie failed with Error 1101 (found on staging; a request with no cookie worked, which is why the first tests passed). 0.7.2 is the version the API already uses, and it works with that import. Remove the override when a new adapter release fixes this, and test a request with a cookie after every adapter upgrade. |
| 24 Nov 2026 | `posthog-js` 1.454.2 | `apps/web` | Sends the browser's analytics events to PostHog (docs/analytics-events.md). Loaded only after the visitor accepts, and with autocapture, page views, recordings, surveys, flags, and the visitor's address all switched off, so only the listed events leave the browser. Writing an event pipeline with identity, batching, and retries ourselves would be long and risky. The project is in PostHog's US region, so event data is stored there; that and the retention period are still part of the open privacy review. |
